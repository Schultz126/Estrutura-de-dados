Lossy Counting

O que é o algoritmo Lossy Counting?

O Lossy Counting (Algoritmo de Contagem com Perda) é um método para identificar itens frequentes em um fluxo de dados (data stream) quando o armazenamento completo dos dados é impraticável. O algoritmo mantém uma tabela de contagem aproximada e divide o fluxo em janelas (buckets) de tamanho w = ⌈1/ε⌉. Periodicamente, ao fim de cada bucket, ele remove (faz pruning) os itens com baixa contagem para controlar o uso de memória. Embora parte da precisão seja perdida (daí o nome), o algoritmo oferece garantias teóricas sobre o erro, controlado pelo parâmetro ε, e assegura que itens verdadeiramente frequentes não sejam perdidos.

Contexto Histórico

Antescedentes nos estudo de fluxo de dados

A área de algoritmos para streams de dados (data streams) começou a ganhar fôlego na década de 1990, quando se tornou claro que muitos dados não podiam ser armazenados inteiramente e depois processados, por exemplo, logs de servidores, tráfego de rede, etc.

Dentro desse contexto surgiu o problema dos itens frequentes (frequent items) ou heavy hitters, ou seja, “quais itens aparecem com frequência significativa no stream?” Esse problema já possuía soluções clássicas para datasets armazenados (por exemplo a abordagem de Misra-Gries de 1982) que foram generalizadas para o contexto de fluxo único.

Um dos desafios era: ao processar um stream de alta velocidade, com enorme volume, a memória e o tempo por item devem permanecer baixos (idealmente constante ou perto disso). Assim, tornou-se necessário desenvolver resumos (sketches / summaries) que mantivessem o essencial da informação sem armazenar tudo.

Surgimento do Lossy Count

Em 2002, Gurmeet Singh Manku e Rajeev Motwani publicaram o artigo “Approximate Frequency Counts over Data Streams” na conferência VLDB 2002.

Nesse trabalho, eles propuseram o algoritmo Lossy Counting como uma solução determinística (não baseada em amostragem aleatória) para o problema de frequent items em streams, com garantias de erro controladas.

Impacto e Relevância

O artigo de Manku & Motwani foi citado amplamente e considerado um dos “best papers” em seu tempo em streaming / resumo de dados.

Ele abriu caminho para diversas variantes e estudos sobre algoritmos de resumo para fluxos, tais como o algoritmo Space-Saving, o esboço de contagens de frequência probabilísticas (ex: sketches), o modelo de janelas deslocantes (sliding window) etc.

Em particular, porque o método era relativamente simples de entender e implementar, ele mostrou como era possível obter memória sublinear no tamanho do stream (dependendo de 1/ε) com erro controlado, uma forma viável para aplicações em tempo real, logs, redes e análise contínua.

Como mencionado, algoritmos como o de Misra-Gries já tratavam itens frequentes em sequências estáticas, mas não diretamente no contexto de streams com memória limitada e necessidade de resposta imediata.Há, também, algoritmos baseados em amostragem (ex: Sticky Sampling) que foram propostos no mesmo trabalho de Manku & Motwani. O Lossy Counting se destaca por não depender de aleatoriedade.

Conclusão Histórica

Em resumo, o Lossy Counting aparece em um momento chave da evolução de algoritmos de fluxo de dados, início dos anos 2000, quando se tornava essencial processar enormes volumes de dados em tempo real com memória limitada. O trabalho de Manku & Motwani formalizou uma abordagem pragmática e teórica para o problema de itens frequentes em streams e influenciou significativamente a comunidade de algoritmos para dados em fluxo.

Algoritmo de janelas (buckets)

Para compreender o algoritmo lossy counting, primeiro é necessário compreender como a divisão das janelas

Definição de janelas

No Lossy Counting, o fluxo é dividido em intervalos chamados janelas ou buckets que determinam quando itens podem ser removidos da tabela de contagem (count table).

Tamanho do bucket é definido por:

w = ⌈1 / ε⌉

Cada bucket possui w elementos consecutivos do stream.
Portanto, se ε = 0.2, então a janela terá 5 itens consecutivos do stream

Uso real do ε

Como é possível observar pela fórmula, quanto menor o valor de ε maior será o tamanho dos buckets, o que resulta em um maior custo de memória para armazenar todos os itens da janela, porém minimiza os erros, tendo em vista a menor variação do valor de δ.

Numeração dos buckets

  • Cada bucket recebe um número sequencial (1, 2, 3, ...) chamado current bucket ID

    • current bucket ID = [N / w]

  • Esse número é usado para calcular o δ; de cada item:

    • δ = current bucket ID - 1

  • O δ representa a incerteza máxima da contagem de um item.
  • Ao subtrair 1 do valor da janela atual, indicamos que o item não pôde aparecer nos buckets anteriores.

Uso real do δ

A fase de pruning será detalhada adiante, porém, em suma, ela consiste em remover buckets antigos e limpar a tabela de contagem a fim de preservar a memória. Neste processo, alguns itens podem ser perdidos (motivo pelo qual este é um algoritmo de perdas), o que impossibilita uma contagem precisa. Para contornar este problema, o cálculo do δ indica quantos itens podem ter existido antes da tabela de contagem ter sido limpa.

Controle de dados através dos buckets

O ponto central do Lossy Counting é o descarte de itens pouco frequentes, a fim de economizar memória.
Isto é feito da seguinte forma:

Se ao final de um bucket, contagem + δ ≤ current bucket ID, então o item é removido;

Esta técnica garante:

  • Itens com contagem baixa são removidos
  • Itens frequentes permanecem com erro controlado

Funcionamento do Lossy Counting

Compreendendo como funcionam as estruturas utilizadas no algoritmo, podemos partir para o estudo de seu funcionamento como um todo

Ideia central

No contexto de fluxo de dados, as informações não são armazenadas em memória, por virem de diversas fontes e em alta velocidade, o que faz necessário que estes dados sejam processados em tempo real. O algoritmo de lossy counting surge como opção para quantificar itens mais frequentes dentro deste fluxo.

Como o peso computacional para armazenar toda a informação da datastream seria muito elevado, este algoritmo descarta itens pouco frequentes enquanto "carrega" elementos para o bucket seguinte. Vale ressaltar que os buckets não são uma forma de armazenamento, mas sim um delimitador de tempo.

Fase de Pruning

O processo de pruning serve para limpar a tabela de contagem. Itens removidos tem sua contagem zerada na tabela, e caso apareçam novamente no stream receberão um novo valor de δ.

Por exemplo, caso o número 4 tenha aparecido no stream no bucket 1, mas sua contagem foi baixa, ele será removido. Quando ele reaparecer no bucket 5, seu valor de δ será 4. Assim, cobrindo a margem de erro, pois não é possível saber se o item 4 apareceu antes do bucket 5.

Resumo

  • Os dados não são armazenados em memória;
  • Buckets não são uma estrutura de armazenamento;
  • O δ indica o erro possível na contagem. O valor exato da frequência do elemento pode ser count + δ;
